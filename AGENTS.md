# Architecture rules

- Portfolio hero uses the original React Bits Pro VaporType at src/components/react-bits/vapor-type.tsx, kept byte-identical and lazy-loaded with a static h1 fallback; keeps Three.js out of the home chunk.

- MedEd Workspace's route gate validates the password and signed, expiring access tokens in an edge function; never embed the password or trust a client-only unlock flag; it is a display gate only, so truly sensitive content needs an authorized backend.
- Keep the supplied MedEd Workspace student prototype unchanged as a public standalone HTML document; mount its iframe eagerly on desktop only (width read synchronously), so it is ready on arrival while phones never download it.
- User-supplied HTML animations stay byte-identical in public/embeds and mount as transparent iframes, preserving their theme handling.
- Lead-form edge functions validate, HTML-escape and send through supabase/functions/_shared/email-utils.ts, and send-service-selection prices services from its own server-side map; client-sent titles and prices are never trusted.
- New/migrated frontend pricing uses src/data/pricing.ts and its formatters to avoid duplicated prices and inconsistent VAT.
- `tiers` in src/data/pricing.ts (Launch, Website Refresh from-price, Business Site) plus `businessOption` page options (5–10 pages, ids `business`/`business-N`, shown via a Pages dropdown in a SelectableCard footer), `addOnCatalogue` and care plans are the only website pricing; industry pages reuse them (proof/FAQs in src/data/segmentPages.ts, retired URLs redirected), keeping scopes, VAT and care terms consistent.
- Aftercare shows once a website is chosen; only a tier card click scrolls to it, once.
- send-consultation requires only the About You fields; description and budget are optional.
- Pricing, segment copy and FAQs never name third-party platform brands; they say "your own booking system" or "your ordering provider", so the offer stays vendor-neutral.
- Free tools are unlisted and noindex (absent from navigation, sitemap and llms files) but their routes and BioPage stay live, so existing client links keep working.
- The services selection bar sends catalogue IDs to /services/start-project via sessionStorage, where they are re-priced and added as a readable summary to the consultation brief; the unchanged send-service-selection function only knows the old IDs, so the bar no longer posts to it.
- ProductStudio stays live at /services/product-studio for its permanent legacy redirects but is unlisted and noindex (absent from services navigation, footer, sitemap and llms-services); the public services offer is web design plus care plans only.
- Service catalogue price lines use shared pricing exports and render through ServicePage, avoiding duplicated amounts on detail pages.
- Pages using usePageDescription synchronise the static description fallback with their managed SEO description and restore it on unmount; this avoids conflicting descriptions without changing the site's static head globally.
- Intake options and plain-English working terms are shared data modules using the pricing catalogue; this makes numeric rules testable without duplicating page values.
- The services picker has two steps (website with Business page options; aftercare: self-managed handover or a care plan). Selection estimates accept only tier/business-N/care IDs plus `self-managed`. Email setup is part of every care plan, not a picker step. No build includes a domain or hosting; hosting comes with care plans.
- Generate portfolio public/llms.txt from projects/profile and public/llms-services.txt pricing from the shared catalogue using scripts/generate-llms.ts; this separates recruiter discovery from commercial pricing without creating a services directory.
- Keep personal identity and hiring-contact constants in the profile module, re-exporting shared experience from pricing; this prevents portfolio code depending on the commercial catalogue.
- SEO derives section branding, default sharing image and fallback service schema from the current pathname; PortfolioSEO is a compatibility re-export and layouts do not set page metadata, avoiding competing head tags.
- Portfolio pages use HiringCTA while commercial pages retain AvailabilityCTA; this isolates hiring contact from commercial offers.
- /work and next-project links show only `listed !== false`, non-coming-soon projects; unlisted case studies keep live routes, so old links still work.
- Portfolio images live under public/images with lowercase-kebab names, at most 1600px wide, and their pixel sizes are recorded in src/data/imageDimensions.ts for <img> width/height; regenerate that map after adding or resizing images so layout space stays reserved.
- Pages are lazy-loaded route chunks in App.tsx while layouts, LegacyRedirect and NotFound stay eager; this keeps the first download small.
- Portfolio pages do not link to /services (the Skills expertise list is intentionally plain text, not links); the only cross-link is from the services footer back to the portfolio, so recruiters are not sent into the Lacuna Digital services site.
- Case studies share src/components/case-study/CaseLayout.tsx and CaseImage and follow one seven-stage story order; data-driven pages place images by `stage`/`with` in projects.ts and the next project follows /work order via src/data/caseStudies.ts to avoid per-project layout hacks.
- The services Hub is a cropped, aspect-reserved lazy Hairline iframe; keep kernel/bench blocks, token pink, themes, controls, reduced motion; no npm.
- React Bits Pro components in src/components/react-bits stay byte-identical and are lazy-loaded; HoverPreview mounts only on idle fine-pointer devices (plain Links otherwise) and BlurHighlight falls back to static marks under reduced motion, keeping the motion package out of first-load chunks.
- MedEd components pages derive from src/data/sparkComponents.ts, sit behind the Spark gate and use only scoped --sc-* tokens.
- The package builder has no step labels, sits above SocialProof, and shows no care terms; edits are quoted per job in services copy.
